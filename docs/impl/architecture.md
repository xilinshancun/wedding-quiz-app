# 系统架构设计

## 整体架构

```
┌─────────────────────────────────────────────────────────────┐
│                        客户端层                              │
├─────────────┬─────────────┬─────────────┬──────────────────┤
│  来宾 H5    │  公共展示页  │  Admin 后台  │   二维码扫描     │
│  (React)    │  (React)    │  (React)    │                  │
└─────────────┴─────────────┴─────────────┴──────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                        API 层                                │
│                    FastAPI (Python)                          │
├─────────────┬─────────────┬─────────────────────────────────┤
│  /api/guest │ /api/display│      /api/admin                 │
│  来宾接口    │  展示接口    │      管理接口                   │
└─────────────┴─────────────┴─────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                       数据层                                 │
│                   PostgreSQL                                 │
├─────────────┬─────────────┬─────────────┬──────────────────┤
│   users     │  questions  │  sessions   │   reward_logs    │
│   用户表     │   题目表     │   会话表     │    奖励日志      │
└─────────────┴─────────────┴─────────────┴──────────────────┘
```

## 核心流程

### 1. 来宾答题流程

```
扫描二维码 → 识别设备 → 获取/创建用户 → 开始会话 → 获取题目 → 提交答案 → 结果反馈
     │                                                              │
     │                                                              ▼
     │                                                    答对：题目下线 + 奖励
     │                                                    答错：题目保留
     │                                                              │
     └──────────────────── 重新扫码 ◄────────────────────────────────┘
```

### 2. 题目竞争机制

```
用户A答题 ──┐
            ├──► 数据库行锁 ──► 检查题目状态 ──► 更新结果
用户B答题 ──┘                        │
                                     ▼
                              题目已被答对？
                              ├── 是：返回"被抢先"
                              └── 否：标记答对 + 发奖励
```

### 3. 设备识别机制

```
首次访问 ──► 生成 device_id ──► 存入 localStorage ──► 创建用户
                                      │
再次访问 ──► 读取 device_id ──────────┘──► 获取已有用户
```

## 技术选型理由

| 组件 | 选择 | 理由 |
|------|------|------|
| 前端框架 | React + Vite | 开发效率高，生态成熟 |
| 样式方案 | TailwindCSS | 快速开发，响应式支持好 |
| 后端框架 | FastAPI | 性能好，自动生成 API 文档 |
| ORM | SQLAlchemy | Python 生态标准，功能完善 |
| 数据库 | PostgreSQL | 事务支持好，并发控制强 |

## 并发控制策略

1. **题目答对判定**：使用 `SELECT ... FOR UPDATE` 行锁
2. **奖励操作**：使用数据库事务保证原子性
3. **会话管理**：通过唯一索引防止重复创建

## 安全考虑

1. **设备识别**：基于 localStorage，简单但足够婚礼场景
2. **管理员认证**：JWT Token，24 小时过期
3. **CORS**：配置允许的前端域名
4. **输入校验**：Pydantic 模型自动校验
